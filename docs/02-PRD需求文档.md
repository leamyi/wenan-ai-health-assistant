# 「问安」AI 问诊助手 · PRD 需求文档

> 查症状，问个安心 —— 就医前自查与面诊准备
> 作者：李孟益 ｜ 版本 V1.0 ｜ 2026-09

## 执行摘要

**产品定位**：轻量级AI健康科普自查工具，聚焦「症状风险分级 + 就诊前准备」细分场景，中立诊前辅助、不做线上诊疗与医药交易；

**北极星指标**：周有效问答渗透率——每周完成≥1次「发送提问并获得完整回答」的访客占比，目标≥40%；

**护栏指标****： **** ****1.**质量：回答正反馈率——「有帮助」评价占总评价的比例，目标 ≥85%；

2.安全：急重症拦截零漏报——考核周期内无「高危症状未触发警示」的用户申诉。红线指标，一票否决，任何增长决策不得以牺牲它为代价。

**P0 共七项**：症状AI问答、疾病科普库、急重症风险提示、结构化引导问诊、回答可信度标注、就诊准备包、单次会话健康时间线；

**差异化依据**：竞品报告显示三家头部产品均为"单次问答范式"，无一提供就诊准备与面诊沟通辅助——问安以此切入竞品薄弱的诊前赛道。

## 二、产品概述

### 2.1 定位与价值主张

给用户一个30秒内获得可靠答案的健康自查入口："查症状，问个安心"。用户出现身体不适时，通过自然语言或结构化引导描述症状，获得基于权威科普知识库的症状解释、居家护理建议与就医决策辅导，并可将碎片化描述自动整理为可携带的一页就诊准备包。

### 2.2 三条合规红线

**不做诊断**：不输出诊断结论，不替代医师判断（国卫办规划发〔2025〕30 号《关于促进和规范"人工智能+医疗卫生"应用发展的实施意见》）；

**不开药**：AI 自动开方已被北京、天津、湖南、福建、上海、江西等多地明令禁止——不输出药品名称、用法用量，不做处方闭环；

**不带货**：无药品推荐、广告、购药跳转等任何商业转化入口，保持诊前工具的中立性。

### 2.3 差异化定位

竞品报告的跨产品共性痛点——单次问答无连续性、不诚实的不确定性、AI结论与医生诊断的信任冲突、就诊材料无法携带进诊室——正是问安的设计原点：问安不做"小号丁香医生"，以高质量知识库、可信度标注、就诊准备包切入头部产品未覆盖的诊前准备细分赛道。

### 2.4 商业模式与免费策略

竞品定价对比给出的核心事实是：豆包用免费问答换流量、丁香靠真人问诊服务收费、京东以问诊为入口靠卖药履约变现——三家收费的前提都是"提供了服务或卖出了商品"。问安的三条红线决定了既不能靠开药带货赚钱，也不能按诊断结果收费，因此商业模式设计如下：

| **阶段** | **策略** | **依据** |
|---|---|---|
| V1.0 MVP | 核心链路完全免费、无注册门槛，第一目标不是收入而是建立信任 | 用户不用担心回答背后有卖货动机，这是与竞品拉开差异的中立性位置（对齐 " 不带货 " 红线） |
| V1.x  迭代 | 维持免费；通过埋点验证 " 信任资产 " （回访率、正反馈率）而非付费转化 | 诊前工具的商业化前提是先用信任留住用户 |
| V2.0  探索 | 仅探索两类变现： ①  对用户透明的会员（问前明码标价、不限次对话、家庭共享、不满意秒退）； ②  面向 B 端的健康科普内容合作 | P2付费订阅体系；绝不在问答内插入商品链接或按结果收费 |
| **红线提醒**：变现入口不得出现在问答链路与警示卡内，会员权益不得包含"更确定的诊断结论"。 |  |  |

### 4.2 功能需求明细

| **编号** | **功能** | **需求描述** | **验收要点** |
|---|---|---|---|
| FR-101 | 症状  AI  问答 | 基于  RAG  医疗知识库的对话式症状科普查询，输出疾病科普、居家护理建议与就医指征， 30  秒内给出首个回答 | 回答必须来自知识库检索；超范围问题返回边界话术 |
| FR-102 | 疾病科普库 | 常见病症图文科普详情页，五段式结构：是什么  /  常见原因  /  居家护理  /  何时就医  /  常见误区 | 内容经医学合规审核，不含药品用法用量 |
| FR-103 | 急重症风险提示 | 高危信号词（胸痛、意识异常、睾丸突然剧痛等）命中即停止对话安抚，置顶输出急诊  /  拨打  120  指引卡；全局免责声明常驻 | 词表双层拦截（提示词层  +  交互层）；拦截零漏报 |
| FR-104 | 结构化引导问诊 | 用户描述过简时进入引导模式，分四步采集：症状细节  →  持续时间  →  过敏史与在用药物  →  既往相关病史，避免漏问关键信息 | 四步可跳过；采集结果并入回答上下文与时间线 |
| FR-105 | 回答可信度标注 | 每条回答按证据强度标注「确定  /  推测  /  证据不足」三态徽章，点击可查看判定依据与知识库条目 | 标注由知识库命中质量自动判定；上线初期以实验开关灰度 |
| FR-106 | 就诊准备包 | 一键将本次问答整理为一页纸面诊材料：结构化主诉、症状时间线、在用药物与过敏史、想问医生的问题清单（ 3-5  条），跨医院通用 | 生成即可预览； P1 支持一键复制  /  导出文本 |
| FR-107 | 单次会话健康时间线 | 自动汇总本次会话的症状、发病时间、病史与用药信息，生成轻量时间线；可保存、回看与编辑 | 仅当前会话范围；清空会话即删除数据（隐私最小化） |

## 六、非功能需求

**性能**：首 token 时延 P90 ≤ 3s；科普页首屏加载 ≤ 1.5s；

**隐私**：匿名可用，不收集姓名、联系方式；不鼓励上传身份证 / 病历原图（吸收豆包用户上传敏感证件的泄露风险教训）；会话数据仅存本地当前会话，一键清空即删；

**内容安全**：知识库内容仅来自公开权威科普，回答不经模型自由发挥；「证据不足」态强制降权表述；

**可用性**：核心链路（进入问答 → 发送 → 获得回答）无注册门槛；免责弹层首访仅一次。

## 八、A/B 实验设计

上线初期安排两组实验，分别验证"可信度标注"与"就医指征前置"两个关键设计决策，均预设护栏指标防止体验劣化。

### 8.1 实验 1：回答可信度标注的可见性

| **要素** | **设计** |
|---|---|
| 假设 | 三态标注帮助用户识别信息边界，抑制 " 对号入座 " 式焦虑，提升回答信任与正反馈率（针对竞品报告中  59.9%  用户 "AI  查病引发焦虑 " 的痛点） |
| 分组 | A  组：不显示可信度徽章（对照）； B  组：显示「确定  /  推测  /  证据不足」徽章（ FR-105  功能开关） |
| 主指标 | 回答正反馈率； MDE +3pp （基线  85% ） |
| 护栏 | 发送率降幅  ≤2pp ； 7  日回访率不下降 |
| 样本量 | n = (1.96+0.84)² × 2×p̄(1−p̄) / δ² ≈ 2,230 ，按  35%  无效曝光余量预估每组约  3,100  次回答曝光，运行  14  天 |

### 8.2 实验 2：就医指征卡片位置

| **要素** | **设计** |
|---|---|
| 假设 | " 何时就医 " 前置为独立警示卡，比折叠在回答末尾更能触达需要就医的用户 |
| 分组 | A  组：就医指征置于回答末尾（对照）； B  组：独立警示卡置于回答顶部 |
| 主指标 | 就医指引点击率； MDE +2pp （基线  7.9% ） |
| 护栏 | 会话跳出率增幅  ≤2pp ；正反馈率降幅  ≤3pp |
| 样本量 | n ≈ 2,890 ，含余量预估每组约  3,900  次回答曝光；若未达标，结论标注 " 方向性 " |
| **实验纪律**：样本量未达预估时只输出"方向性结论"并以护栏指标约束决策；急重症相关改动（实验 2）在任何情况下不允许以转化率为由弱化警示强度。 |  |

## 十、风险与合规清单

产品全生命周期须持续对照以下合规要求（依据竞品报告第八章及引用法规）：

| **#** | **风险项** | **应对措施** |
|---|---|---|
| 1 | AI  输出被当作诊断（替代医师判断） | 三条红线写入提示词与产品文案；全局免责横幅常驻；首访免责弹层强制确认 |
| 2 | AI  自动开方  /  审方（多地明令禁止） | 不做处方闭环（不做清单第一条）；不输出任何药品名称与用法用量 |
